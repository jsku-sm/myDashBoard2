생기부 AI 초안 생성 수정 — 2026-11-13

확인한 문제
- 기존 README의 [openai] api_key/model 설정만으로는 생기부 생성기가 활성화되지 않았습니다.
- [quiz_ai], [snorkl], 서버 환경변수에 있는 기존 API 키도 읽지 못했습니다.
- API 오류의 원인을 충분히 구분하지 못했고, AI는 작성했으나 저장이 실패하면 작성 칸이 비어 있는 것처럼 보였습니다.
- 실제 배포 화면의 오류 문구, 비공개 Secrets, API 결제 상태는 확인하지 않았으므로 선생님 환경에서 발생한 원인은 아직 단정할 수 없습니다.

수정 내용
1. 기존 공식 OpenAI API 키와 해당 모델 설정을 재사용합니다. 우선순위는 생기부 전용 → 공통 OpenAI → 최상위 Secrets → 서버 환경변수 → 퀴즈 → 수행평가입니다.
2. 키가 있고 별도 사용 설정이 없으면 교사가 생성 버튼을 눌러 사용할 수 있습니다. [school_record_ai] enabled=false로 명시한 설정은 그대로 존중합니다. 다른 주소에 연결된 제공업체의 키는 공식 OpenAI로 보내지 않습니다.
3. API 키·모델·권한·사용 한도·응답 중단·연결 실패를 구분해 안내합니다. API 키나 학생 자료를 오류 메시지에 출력하지 않습니다.
4. 자료 확인 → 생성 요청 기록 → AI 작성 → 결과 저장 단계를 화면에 표시합니다.
5. AI 작성 후 저장이 실패해도 완성된 초안을 작성 칸에 표시합니다. 생성된 초안 저장 다시 확인 버튼으로 AI를 재호출하지 않고 저장할 수 있습니다. 교사가 이후 수정한 내용도 보존합니다.

적용 방법
- 이 ZIP은 전체 프로젝트가 아닌 변경 파일입니다. 압축을 풀고 기존 코드 저장소의 같은 경로에 덮어쓰세요.
- 실행 파일 3개: record_core/ai.py, record_core/writer_view.py, record_core/semester.py
- tests/는 검증용이며 앱 실행에는 필수가 아닙니다.
- ZIP 자체를 올리는 것만으로 실행 코드가 바뀌지는 않습니다. 압축을 푼 파일을 올려야 합니다.
- 데이터 저장소 jsku-sm/class-dashboard-data, 기존 암호화키, 학생 데이터는 수정하지 않습니다.
- 학생들이 작업하지 않는 시간에 적용하고 저장 대기 작업이 없는 상태에서 필요한 경우 Streamlit 앱을 재시작하세요.
- 연결된 GitHub의 쓰기 권한이 없어 코드 저장소에 직접 반영하지 않았습니다.

설정 확인
생기부 생성 버튼 위의 ‘AI 연결 상태 · 설정 도움말’을 확인하세요.
기존 API 키가 인식되고 생기부 AI를 꺼둔 설정이 없다면 새 키 입력은 필요 없습니다.
사용 안 함으로 표시되면 Streamlit 앱 Settings → Secrets의 기존 [school_record_ai] 구역에서 enabled = true로 변경하세요.
같은 구역을 중복 추가하지 마세요. API 키를 GitHub 코드, 채팅이나 스크린샷에 넣지 마세요.
모델 설정에 ‘사용 가능한 모델 이름’ 같은 안내 문구가 들어 있으면 실제 모델명으로 수정해야 합니다.
키가 전혀 없거나 유효하지 않거나 사용 한도를 초과했다면 해당 API 계정 설정을 확인해야 합니다. 코드만으로 이 상태를 해결할 수는 없습니다.

검증
관련 테스트 162개 통과. 기존 공통 AI 설정 → 자료 선택 → 실제 Responses 요청 어댑터(모의 HTTP) → 초안 표시·저장 흐름을 검증했습니다.
저장 실패 후 초안 표시, 교사 수정 보존, AI 추가 호출 없이 저장 복구, 명시적 비활성화, 다른 제공업체 키 차단, 오류별 안내도 검증했습니다.
실제 학생 자료 전송, 유료 AI 호출, 운영 GitHub 데이터 변경은 하지 않았습니다. 실제 배포 환경에서 API 연결 성공 여부는 적용 후 확인이 필요합니다.
