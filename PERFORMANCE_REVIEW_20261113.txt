25명 동시 사용 성능 점검 및 생기부 개선 통합본

적용한 개선
1. 교사전용 메뉴 10개를 모두 실행하던 방식을 바꾸어 선택한 메뉴만 실행합니다. 생기부 자료의 원격 조회가 다른 교사 메뉴 사용 중 반복되지 않습니다.
2. 수업 상세의 공지·자료·과제·달력도 선택한 화면만 실행합니다. 작성 중 글과 선택 값은 탭 전환 후 유지하며 확정 체크는 다시 확인합니다.
3. 퀴즈 실행 파일 65개, 약 1.50MB를 매번 다시 읽고 검사하던 작업을 파일 변경 시에만 다시 계산합니다. 파일 교체·누락·잘못된 버전 검사는 유지합니다.
4. 수행평가 저장 요청은 같은 앱 서버 안에서 순서대로 처리합니다. 저장된 상태와 버전을 재사용하고, 외부 변경과 충돌하면 최신 자료를 다시 읽어 병합합니다. 변경이 없는 동작은 불필요한 저장을 하지 않습니다.
5. 동시에 들어온 수다노트 등은 0.08초 동안 모아 한 번에 저장합니다. 실제 GitHub 저장이 끝나기 전에는 저장 완료로 처리하지 않습니다.
6. 보상 게임의 최고기록 계산에서 같은 기록을 게임 수만큼 반복해서 읽던 부분을 한 번만 읽도록 바꿨습니다.
7. 앱 시작 검사에서는 코드 전체 대신 필요한 처음 256자만 읽습니다.

생기부 개선도 포함
자료 선택 → 읽기 쉬운 학습 내용/응답/힌트/재도전 확인 → AI 초안 생성 → 교사 검토 → 그대로 확정 또는 수정 저장. 수식은 수학 기호로 렌더링하고, 추가 사실 메모와 문장 수정은 필수가 아닙니다. 기존 상단 안내 배너 삭제도 유지합니다.

검증
- 가상 학생 25명이 동시에 수행평가 상태를 저장: 25건 모두 보존, 앱 내부 충돌 0회.
- 가상 학생 25명이 수다노트를 제출: 원본 CSV와 학생별 암호화 기록을 모두 확인.
- 변경 없는 퀴즈 실행 파일 검사 25회: 큰 파일을 다시 읽지 않음. 실제 파일 변경·누락 검출 테스트 유지.
- 가상 저장소에 요청당 4ms 지연을 넣은 비교 실험: 기존 296회 요청/129회 충돌, 수정 52회 요청/0회 충돌. 상세 숫자는 PERFORMANCE_SYNTHETIC_20261113.json 참고. 이 값은 실제 수업의 속도나 처리 시간 보장이 아닙니다.
- 전체 비브라우저 테스트: 2,212개 통과, 기존부터 현재 코드/환경과 맞지 않던 8개 실패 유지. 새 실패 없음. 8개는 과거 테스트의 클라우드 연결 설정, 관찰기록 인증 모의 설정, 4개의 암호화키 없는 GitHub 모의 환경, 예전 퀴즈 경로, 예전 로그인 문구 검사입니다.
- 실제 학생 자료와 실제 GitHub 저장소를 변경하지 않았고 유료 AI 요청도 보내지 않았습니다.

남은 구조적 한계와 적용
- 기존 jsku-sm/class-dashboard-data 저장소, 폴더, 암호화키, 파일 형식은 유지합니다.
- 수행평가는 여전히 공유 state.enc 파일을 저장합니다. 자료 누적·큰 첨부·GitHub 응답 지연은 남을 수 있습니다. 기록 분할이나 외부 데이터베이스 이전은 이번에 하지 않았으며, 필요 시 별도 확인이 필요합니다.
- 최대 25명의 같은 앱 서버 사용을 가정했습니다. 여러 앱 서버에서 같은 데이터 저장소를 동시에 수정하는 운영은 별도 설계가 필요합니다.
- 실제 배포 서버 사양, 학교 와이파이, 25대 기기의 동시 브라우저 접속은 이번 환경에서 측정하지 못했습니다.
- 학생이 작업하지 않는 시간에 코드 파일을 적용하세요. 저장 대기 0건을 확인한 뒤 필요하면 Streamlit 앱을 재시작합니다. Codespaces를 사용할 필요는 없습니다. 기존 Secrets와 데이터 저장소의 파일은 교체하지 마세요.
- 패치 ZIP은 동일한 폴더 경로에 적용하거나, 전체 코드 ZIP을 사용하세요. 이전 PATCH_SHA256_20261113.json은 당시 감사 패치의 검증표이며, 이번 통합본 검증표는 PERFORMANCE_PATCH_SHA256_20261113.json입니다.
