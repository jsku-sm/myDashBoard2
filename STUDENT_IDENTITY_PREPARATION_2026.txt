학생 기록 분리 준비 · 기존 자료는 2026학년도

확인된 운영 조건
- 교사 계정은 실제 수업용입니다.
- Codespaces 앱을 사용하지 않습니다.
- 매년 신입생에게 10101 같은 학번을 재사용합니다.
- 현재 학생 명단과 기록은 모두 2026학년도 자료입니다.

이번에 준비한 규칙
- 학생마다 바뀌지 않는 student_uid를 둡니다.
- 학년도별 school_number(화면 학번), 학급, 재학 상태를 따로 연결합니다.
- 2026년 10101의 기존 자료는 그 학생에게 계속 귀속합니다.
- 2027년의 새 신입생 10101은 다른 student_uid를 받습니다.
- 같은 학생이 진급하면 기존 student_uid를 명시적으로 연결합니다.
- 학년도·학번이 정확히 일치할 때만 학생을 찾으며, 이전 학년도 계정으로 자동 연결하지 않습니다.
- 같은 학년도에 이미 사용한 학번은 계정을 보관 상태로 바꿔도 다른 사람에게 재배정하지 않습니다.
- 기존 교사 ID와 비밀번호 해시는 이 도구가 변경하지 않습니다.

현재 상태
검토용 코드만 준비했습니다. 앱 로그인과 저장 경로에 아직 연결하지 않았습니다.
2027학년도 명단을 실제 앱에 등록하기 전에 운영 연결 및 이전 검증을 완료해야 합니다.
검토 결과 JSON에는 can_apply=false, activation=preview_only가 표시됩니다.
적용 명령이나 자동 이전 버튼은 의도적으로 제공하지 않습니다.

검토 도구의 입력·출력
입력: 실제 데이터 저장소의 별도 로컬 사본. 코드 저장소를 입력하는 것이 아닙니다.
출력: 학생 고유번호 대응 초안, 변경하지 않을 교사 ID, 파일별 해시·행 수,
      현재 명단에 없는 학생 기록, JSON 내부 연결의 추가 검증 목록, 암호화 자료의 미검증 표시.
비밀번호 해시·키 원문은 출력하지 않습니다. 학생 이름·학번이 포함될 수 있으므로 출력은 비공개로 보관합니다.

실행 예시 (개발자용)
python scripts/preview_student_identity.py --snapshot /비공개/데이터저장소사본 --year 2026 --output /비공개/identity-preview/plan-2026.json
출력 폴더는 미리 준비해야 하며 원본 사본의 바깥이어야 합니다. 이미 있는 파일은 덮어쓰지 않습니다.
이 명령은 네트워크에 접속하지 않고 원본을 수정하지 않습니다. 암호화 자료를 복호화하지도 않습니다.

실제 이전 전에 제시할 변경 목록
1. 데이터 저장소와 현재 암호화 키를 각각 별도 백업하고, 백업에서 표·첨부가 열리는지 확인.
2. 명단·수다노트·관찰·상벌점·퀴즈·게임·수행평가·생기부의 학생 연결 대응표 점검.
3. 삭제한 계정의 기록과 같은 학번에 서로 다른 이름이 붙은 자료는 자동 통합하지 않고 확인.
4. JSON 내부의 퀴즈 대상·방과후 참여자·수업 회원, 수행평가 state.enc 및 학생 자료함·첨부 연결 검사.
5. 임시 환경에서 로그인은 학번으로 유지하면서 서버가 현재 학년도→student_uid를 선택하도록 연결.
6. 기존 학생별 원본·현재본·암호화 이력을 보존하고 별칭 연결을 검증. 과거 경로의 일괄 이름 변경 금지.
7. 학생별·자료종류별 이전 전후 건수, 내용 해시, 교사 작성자·학년도·학기·과목, 첨부 접근 비교.
8. 2027년에 같은 학번을 가진 새 학생이 2026 기록을 볼 수 없는지 확인.
9. 사용자에게 검증 결과·실제 수정 파일 목록·복구 절차를 제시한 뒤 운영 적용 승인 요청.

검증 한계
현재 실제 데이터 저장소 내용에는 접근하지 못했습니다. 테스트는 가상 자료로 수행했습니다.
따라서 실제 학생별 대응표, 운영 자료 건수, 암호화 자료 내부 연결이 검증됐다고 주장하지 않습니다.
