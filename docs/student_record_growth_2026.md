# 생기부 초안: 성취기준·성장·학습 태도 중심 작성 개선

작성일: 2026-11-16  
기준 소스: 사용자가 제공한 `myDashBoard2-main (1116).zip`  
정책 버전: `school-record-2026-grounded-growth-v1`

## 1. 이번 수정의 목적

문항 번호와 정답·힌트·재도전 횟수를 나열하는 초안에서, 확인된 활동을 근거로 학생의 수학적 이해·적용, 학습 태도, 변화, 다음 학습 목표를 연결하는 참고 초안으로 개선했다.

작성의 기본 흐름은 다음과 같다.

1. 실제 수행과 확인된 성취를 내용별로 묶는다.
2. 그 수행이 보여 주는 개념 이해·문제 적용을 관찰 범위에서 해석한다.
3. 질문·설명·수정·도움 활용·자기성찰 등 구체적인 행동을 학습 태도와 연결한다.
4. 이전/이후 비교 근거가 있으면 변화·성장을 설명한다. 비교 근거가 없으면 현재 수행과 확인된 후속 학습 목표를 쓴다.

네 요소를 모든 문단에 강제로 넣지 않는다. 기록에 없는 태도·성장·성과를 보충하거나, 미래 성취를 보장하는 칭찬 문장을 만들지 않도록 지침을 구성했다.

## 2. 실제 적용 위치

학생별 생성과 선택 학생 일괄 생성은 모두 같은 경로를 사용한다.

`writer_view._generate → SemesterRecords.generate → RecordAI.draft`

기존 자료함의 생성 경로도 같은 `RecordAI.draft`를 사용하므로 기본 작성 정책을 함께 적용한다. 새 지침은 새로 생성하는 초안부터 적용하며, 저장된 교사 문장은 자동 재작성하지 않는다.

| 파일 | 변경 내용 |
|---|---|
| `record_core/writing_policy.py` | 기재요령 출처·우선순위, 성장 중심 생성 지침, 근거 범위 제한, 주제별 성취기준 후보 연결 |
| `record_core/curriculum_common2.json` | 공식 공통수학2 성취기준 20개, 원문 출처와 페이지, 키워드·주제 연결 정보 |
| `record_core/ai.py` | 익명화한 확인 근거와 동일한 작성 맥락을 전송하고, 적용 정책·기준을 생성 결과에 기록 |
| `record_core/semester.py` | 학년도 전달, AI 원문 이력 보존, 개별·일괄 생성 공통 적용 |
| `record_core/service.py` | 실제 전송과 동일한 입력 미리보기, 교사 최종 검토 보조 검사, 줄바꿈 1B 계산 |
| `record_core/writer_view.py` | 적용 지침과 성취기준 후보 표시, 검토·수정 안내, 합산 분량 안내 |
| `record_core/view.py` | 기존 자료함의 교사 검토·수정 안내 및 AI 원문 이력 유지 |

실행에 필요한 파일은 위 7개이다. 함께 제공한 테스트와 이 안내 문서는 검증·유지보수 자료이다.

## 3. 성취기준 연결 방법

교사가 선택하고 확인한 자료의 활동 제목과 사실 문장에서 관련 주제를 찾는다. 관련 기준을 `writing_context.curriculum.standards`에 넣고, 기준마다 연결된 근거 ID를 남긴다. 학생의 원문·날짜·출처는 기존 근거 입력에 보존한다.

| 관찰 내용 | 참고 기준 | 해석 범위 |
|---|---|---|
| 함숫값 읽기, 두 집합의 대응이 함수인지 판단 | 10공수2-03-01 | 함수 개념·그래프의 관련 기초 수행 |
| 합성함수의 값 구하기 | 10공수2-03-02 | 제시된 합성 계산 수행. 원리를 말로 설명했다는 뜻으로 확대하지 않음 |
| 일대일함수·일대일대응을 더 구분하고 싶다는 성찰 | 10공수2-03-01 | 자기점검과 후속 학습 목표. 역함수 기준 달성으로 확대하지 않음 |
| 실제 역함수 문제·풀이 | 10공수2-03-03 | 기록에 나타난 역함수 관련 수행 |
| 유리함수·무리함수의 실제 활동 | 10공수2-03-04·05 | 해당 활동에서 확인한 성질·그래프 등으로 한정 |

공식 영역별로 도형의 방정식 7개, 집합과 명제 8개, 함수와 그래프 5개를 포함한다. 공통수학1에 공통수학2 기준을 자동 적용하지 않는다.

이 기능은 주제에 맞는 **참고 후보**를 고른다. 성취 수준을 자동 채점하거나 기준 전체 달성을 인증하지 않는다. 제목이 넓거나 표현이 모호하면 기준이 연결되지 않을 수 있다. 이때 확인한 사실에 단원·구체 개념을 보완하거나 해당 기준을 교사가 확인한다. 기준 번호를 직접 적더라도 그 번호 자체가 성취 증거가 되지는 않는다.

## 4. 사용자가 제시한 사례에 적용한 서술 예시

아래는 변경한 작성 원칙을 설명하기 위한 예시이다. 실제 API 실행 결과 또는 확정용 문장으로 제시한 것이 아니다.

> 함수와 그래프 단원의 기초 퀴즈에서 그래프를 통해 함숫값을 읽고 합성함수의 값을 구하며, 두 집합 사이의 대응 관계가 함수의 조건을 만족하는지 판단하는 문항을 추가 힌트나 재시도 없이 정확하게 해결함. 함수의 기초 개념을 제시된 문제에 적용하는 모습을 보임. 학습 후 자기성찰에서 일대일함수와 일대일대응의 차이, 항등함수와 상수함수의 의미를 구분하고자 하는 노력을 드러냄. 일차함수와 이차함수의 식을 바탕으로 함수의 종류를 판별하는 방법을 더 익히고 싶다는 목표를 밝히며, 자신의 이해를 점검하고 보완할 학습 과제를 구체화하는 자기주도적 학습 태도를 보임.

단일 시점 기록만 있는 이 사례에는 '이전보다 향상됨'을 추가하지 않는다. 정답만으로 설명·증명·완전한 숙달을 인정하지 않는다. 힌트 미사용을 모든 외부 도움의 부재로 해석하지 않는다.

## 6. 교사 검토·수정과 분량

공식 2026 지침 인쇄19쪽은 AI 생성 자료를 서술형 항목에 그대로 입력하는 행위를 금지하고, 실제 수행과 무관한 허위·과장 및 기재 유의사항을 교사가 최종 확인하도록 한다.

이에 따라 AI 원문은 참고 초안으로 저장할 수 있고, 완성본 저장 때에는 교사의 검토·수정이 필요하다. 앱은 원문과 동일한 글 또는 공백·구두점만 바뀐 글의 확정을 거부한다. 직접 작성으로 전환하더라도 기존 AI 원문 이력을 보존한다. 처음부터 교사가 직접 작성한 글에는 AI 원문 비교를 적용하지 않는다. 확인·수정 메모는 선택 사항이다.

동일성 비교는 앱이 선택한 검토 보조장치이다. 공식 지침이 이 알고리즘이나 최소 수정량을 정한 것은 아니며, 글을 조금 고쳤다는 이유만으로 사실의 타당성이나 기재 적합성이 보증되지 않는다.

공식 인쇄208쪽에 따르면 **2022 개정 교육과정을 적용하는 2026학년도 1~2학년의 공통수학1·2는 합산 한글 기준500자(1500B) 이내**이다. 각 과목에 각각500자라는 뜻이 아니다. 앱의 목표 글자 수와 저장 바이트 한도는 작업용이며, 다른 과목·학기의 전체 기록을 자동 합산하여 한도 적합성을 판정하지 않는다. 나이스 최종 입력 전에 합산 분량을 확인해야 한다.

참고 바이트 계산은 UTF-8을 사용하고 CRLF·CR을 LF로 통일하여 줄바꿈을1B로 계산한다. 특수문자와 실제 나이스 입력 결과는 최종 확인한다.

## 7. 적용 방법

1. 현재 운영 코드의 백업을 남긴다.
2. 패치 ZIP을 풀고 `myDashBoard2-main` 안의 `record_core` 파일을 현재 앱의 같은 경로에 덮어쓴다. 특히 신규 `writing_policy.py`와 `curriculum_common2.json`을 함께 넣는다. 전체 ZIP을 이용하는 경우에는 해당 ZIP을 수정된 전체 소스로 사용한다.
3. GitHub에 코드를 반영한 뒤 사용 중인 Streamlit 배포에서 새 버전을 반영하거나 재시작한다.
4. 생기부 작성기에서 학년도·학기·공통수학2·학생을 선택하고 근거 자료를 확인한다.
5. 'AI에 전달할 내용 확인'에서 함수 개념·합성함수 등 해당 기준 후보가 연결되는지 확인한 뒤 새 초안을 생성한다. 기존 글이 있는 경우 '이미 작성한 글도 보관한 뒤 새 초안으로 바꾸기'를 사용한다.
6. 학생 실제 수행과 문장별 근거를 대조하여 교사가 검토·수정한 뒤 완성본으로 저장한다.

이번 제공물은 수정 코드와 적용 자료이다. 운영 중인 사이트에 직접 배포하지 않았다. 새 정책을 적용하려면 코드를 반영하고 초안을 새로 생성해야 한다.

합성 학생·교사 자료, 메모리 암호화 저장소, 모의 HTTP/AI 응답을 사용했다. 실제 학생 자료를 외부 AI에 전송하거나 운영 저장소에 쓰지 않았다. 실제 모델의 문장 품질과 모든 해석의 사실적 타당성은 이 테스트만으로 보증하지 않는다.

1차에는 '함숫값을 읽고…' 문장의 기준 연결 누락1건을 발견했다. 자연스러운 조사 표현을 처리하도록 키워드를 보완한 뒤 동일한190개 검사를 재실행하여 통과했다. 검증 상세는 함께 제공한 `record_writing_policy_verification.json`에 담았다.

## 9. 되돌리기
