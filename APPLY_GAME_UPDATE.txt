게임 화면
1. 수학 플레이 → 게임으로 배우기에서 선택한 게임을 현재 화면에 고정된
   플레이 영역에 엽니다. 긴 목록을 내려가서 선택해도 화면 위쪽을 찾아
   다시 스크롤할 필요가 없도록 했습니다.
2. 아케이드 20종에는 형광색 '← 모든 게임 목록' 버튼을 위쪽에 배치하고
   게임 안에서 스크롤해도 유지합니다. 아바타/단계별 개념퀴즈에도
   동일한 의미의 고정 목록 복귀 버튼을 제공합니다.
3. 단원 마무리 5종에도 목록 복귀 버튼을 제공합니다. 전체화면에서도
   버튼이 보이며, 아직 반영되지 않은 조작 기록을 서버에 반영한 다음
   목록으로 돌아갑니다. 활동 시간과 보상 규칙은 기존대로 유지합니다.

속도 개선
- 게임 조작·기록 갱신에서 대시보드 전체 대신 해당 게임 영역만 실행합니다.
- 플레이 화면에는 필요하지 않은 최근 기록/전체 단원 통계를 매번 보내지
  않습니다. 성장기록과 생기부 자료의 원본 기록은 그대로 유지합니다.
- 승인된 학생 자료를 가져온 다음, JSON 해석과 화면 데이터 생성은
  다른 학생의 저장을 막지 않는 위치에서 처리합니다.
- 암호화 자료함 저장 시 전체 학생·전체 표를 복사하던 처리를,
  변경된 학생의 해당 표와 연결된 문제/활동 자료만 복사하도록 줄였습니다.
- 기존 저장 대기열, 재시도, 충돌 검사, 학년도 구분과 암호화를 유지합니다.

검증
- Python 관련 자동 테스트 345개 통과.
- 실제 Streamlit 실행 엔진으로 아케이드 20종, 아바타/개념퀴즈,
  단원 마무리 5종의 입장·복귀를 검증했습니다.
- 게임 화면 전환 44회에서 바깥 대시보드 실행 횟수는 최초 1회로 유지됐습니다.
- 25개 동시 작업의 수다노트 저장, 수행평가 저장, 게임 참여/정답 기록을
  가상 계정·모의 저장소로 검증했습니다. 중복/다른 학생 자료 혼입 없이 통과했습니다.
- JavaScript 아케이드 테스트 31개, 보상 게임 테스트 7개와 DOM 동작 검증 통과.
- 브라우저 기록 대기열·저장 재시도·저장 후 목록 이동 및 게임 화면 유지 검증.
- 저장 대상을 줄여도 각 자료 종류의 암호화 파일 내용·버전 식별값·첨부파일
  연결이 동일하고, 삭제 후 빈 표도 보존되는지 검증했습니다.

검증 범위
- 이 환경의 브라우저 실행/로컬 미리보기 연결 제한 때문에 실제 화면 캡처를
  통한 데스크톱·모바일 배치 검증은 완료하지 못했습니다.
- 실제 학생 자료/운영용 AI/실제 GitHub 저장 호출은 테스트에 사용하지 않았습니다.
- 학교 네트워크와 Streamlit 서버에서 25대 실기기를 연결한 부하 시험은
  별도로 필요합니다. 모든 상황에서 버퍼링이 없다고 보장하는 수정은 아닙니다.
- 이 ZIP 제공만으로 운영 GitHub/Streamlit에 자동 반영되지는 않습니다.

적용 후 확인할 동작
1. 목록 마지막 게임 선택 → 현재 화면에서 열리는지 확인.
2. 게임 화면 안에서 스크롤 → 형광색 목록 버튼 확인.
3. 아바타, 단계별 개념퀴즈, 단원 마무리 활동에서도 목록 복귀 확인.
4. 2~3명으로 저장 상태·성장기록 확인 후 실제 학급에서 사용.
