왜 다시 수정했나요?
이전 코드는 바깥 게임 창만 현재 화면에 고정하고, 내부 게임은 원래 크기로
그려서 화면 아래가 잘리거나 내부 스크롤이 필요했습니다.

교정한 동작
- 현재 보이는 화면의 가로·세로 크기에서 상단 앱 바와 여백을 뺍니다.
- 문제, 게임판, 조작 버튼, 목록 복귀 버튼을 포함한 실제 콘텐츠 크기를
  측정하여 가로·세로 비율을 유지한 채 한 화면 안에 맞춥니다.
- 브라우저 배율, 창 크기, 태블릿 방향, 확대 시 보이는 영역의 변경을
  감지해 다시 계산합니다. 콘텐츠를 잘라 숨기는 방식이 아닙니다.
- 카드 짝 맞추기의 12장 전체가 한 판으로 들어오도록 격자와 크기를 정리했습니다.
- 제목·사운드·중복 안내의 큰 여백을 줄이고 게임판과 조작부를 함께 배치합니다.
- 게임 내부 스크롤과 발사 후 자동 스크롤을 제거했습니다.
- 아케이드, 단계별 개념퀴즈, 아바타 화면, 단원 마무리 활동에 같은
  화면 맞춤 처리를 사용합니다. 보상 게임의 별도 전체화면도 함께 맞춥니다.
- 확대 비율이나 화면 높이에 따라 게임 전체가 작아질 수 있습니다.
  화면에 모두 담기 위한 비율 조정이며, 카드·문제·조작 버튼은 유지합니다.

기존 처리 유지
- 게임 상태, 정답, 보상, 점수, 기록 저장, 참여코드와 권한 검사는 기존대로입니다.
- 게임에서 목록으로 돌아갈 때 아직 반영되지 않은 기록을 먼저 반영합니다.
- 동시 접속 시 게임 영역만 실행하고, 필요한 학생 자료만 처리하는 개선을 유지합니다.
- 학생 자료 저장소 class-dashboard-data, 기존 자료와 Secrets/암호화키는 변경하지 않습니다.

검증 결과
- Python 관련 자동 테스트 345개 통과.
- 아케이드 JavaScript 테스트 33개와 보상 게임 테스트 7개 통과.
- 7개 화면 크기 × 6개 배율(80/100/125/150/175/200%) × 5개 콘텐츠 높이,
  총 210개 계산 조건에서 전체 콘텐츠가 가로·세로 화면 안에 들어가는지 검증했습니다.
- 화면 맞춤 제어기의 배율 변경·가로세로 전환·콘텐츠 증가·종료 후 복원 동작 검증.
- 20개 아케이드 이동, 아바타/개념퀴즈, 보상 게임 5종, 저장 후 복귀,
  기존 게임 상태 유지와 동시 저장 시험 통과.
- 실제 브라우저/실기기에서 화면을 캡처해 확인한 결과는 아닙니다.
  배포 환경에서의 최종 배치와 터치 조작은 추가 확인이 필요합니다.
